> **Synthetic demonstration notice:** This document is entirely fictional test content created only to demonstrate retrieval and chunk-size behavior. It is not real financial-services policy, legal advice, compliance guidance, operational guidance, or institutional instruction. It contains no real customer data. Names, codes, thresholds, dates, queues, and workflows are invented and must never be used for live decisions.

## 1. Purpose and Safety Boundary

This long runbook is fictional evaluation material. It simulates an escalation workflow without describing any real control, customer, threat, institution, or legal obligation. Scores, tiers, deadlines, queues, and tags are invented. The document tests retrieval of ordered steps, thresholds, scoped exceptions, and distant cross-references.

## 2. Synthetic Signal Vocabulary

A signal is a lab assertion attached to a fabricated event. A score is a synthetic integer from 0 through 100. **Tier Amber begins at score 41. Tier Red begins at score 73.** Scores below 41 remain Tier Green. Threshold equality is inclusive. These tiers have no production meaning.

## 3. Intake Preconditions

Confirm the record displays RUN-CHUNKLAB-202 and the synthetic classification. Remove any exercise input that resembles personal data or a credential. Assign a drill ID and record the score source as **LAB-SCORE-V1**. Never estimate a missing score.

## 4. Ordered Response Sequence

For Tier Amber and Tier Red, execute the steps in this exact order: **preserve, freeze, verify, escalate**. Preserve the fictional evidence snapshot first. Freeze only the simulated workflow state second. Verify the supplied drill assertions third. Escalate to the lab destination fourth. Reordering is a failed drill even if all four words appear.

## 5. Step One - Preserve

Create an immutable-looking but purely textual exercise snapshot containing event labels, score, tier, and cited headings. The snapshot is not sent anywhere. Record marker **PRESERVE-COMPLETE** before moving forward. Do not include names, account data, network addresses, or device identifiers.

## 6. Step Two - Freeze

Set the fictional state to **LAB-FROZEN**. This does not freeze an account, credential, payment, device, or cloud resource. It simply prevents later rehearsal paragraphs from changing the initial score. If preservation is incomplete, stop; the order cannot be repaired by freezing first.

## 7. Step Three - Verify

Compare the score, signal labels, and scenario tag with the facilitator packet. Verify each assertion independently. A device mismatch alone is normally one synthetic signal, but the next heading defines a narrow exception that changes how that signal is counted.

## 8. Boundary Exception - SIM-ONLY Drill Tag

When the exact exercise tag is **SIM-ONLY**, suppress **device mismatch alone** as an escalation signal. SIM-ONLY does not suppress amount velocity, impossible-sequence markers, repeated challenge failures, or any Tier Red score. It does not change the ordered preserve, freeze, verify, escalate sequence. The condition and exception are separated across Sections 7 and 8 intentionally.

## 9. Step Four - Escalate

After verification, route Tier Amber to **LAB-FRAUD-AMBER** and Tier Red to **LAB-FRAUD-RED**. Tier Green remains in **LAB-FRAUD-OBSERVE**. Include the score and exact cited threshold heading. A SIM-ONLY tag changes one signal, not the destination implied by a supplied final score.

## 10. Acknowledgement Deadline

The receiving lab queue must record a fictional acknowledgement within **27 minutes** of the escalation marker. This is a rehearsal target, not a service level, legal deadline, or real response promise. If the timer is paused by the facilitator, record **ACK-TIMER-PAUSED**.

## 11. Threshold Collision Review

At score 41, use Tier Amber. At score 73, use Tier Red. If a narrative label conflicts with the numeric score, the numeric threshold controls within this document, and the mismatch is noted. No interpolation or external scoring rule is allowed.

## 12. Synthetic Velocity Exception

The label **BATCH-REPLAY** prevents repeated replay rows from being counted as separate velocity events, but it does not reduce an explicitly supplied final score. This scoped exception resembles a contradiction only when its scope is omitted.

## 13. Cross-Reference to Duplicate Intake

When the drill also carries **DUPLICATE-CANDIDATE**, consult **PROC-CHUNKLAB-101 Section 4, “Stage Two - Normalize the Candidate Pair,”** before verification closes. The fraud runbook does not redefine the correlation key. It consumes the normalized candidate state and continues its own ordered sequence.

## 14. Cross-Reference Precedence

RUN-CHUNKLAB-202 controls synthetic fraud tiering. PROC-CHUNKLAB-101 controls synthetic duplicate normalization. Neither document controls the other domain. A retrieval answer must state which document and heading supplies each fact.

## 15. Tier Amber Review Packet

The Amber packet contains the preserved snapshot, verification checklist, score, and acknowledgement clock. It omits speculative identity narratives. The lab reviewer checks that score 41 is inclusive and that the ordered sequence is complete.

## 16. Tier Red Review Packet

The Red packet contains the same safe fields plus a facilitator note explaining why the supplied score is at least 73. The packet never claims a crime, loss, account takeover, or reportable event. It is a synthetic severity exercise only.

## 17. Closure Conditions

Close only after acknowledgement, citation review, and synthetic-data confirmation. The closure code is **LAB-FRAUD-CLOSED**. An unacknowledged escalation remains open in the exercise even if every other step is present.

## 18. Prohibited Interpretations

Do not treat the score as a probability, the tiers as institutional risk bands, the freeze step as authority to restrict anything, or the acknowledgement target as a customer commitment. Do not merge this runbook with real guidance.
